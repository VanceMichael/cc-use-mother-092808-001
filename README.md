# 宏观预测征集与发布后端

面向央行焦点调查（Focus Survey）类场景的宏观预测征集、共识计算、发布水位与事后回测后端。
解决"只保存每周最终数字"的治理缺口：**每一次修订、理由、撤回都留痕；迟到修订不能覆盖
已发布水位；任何报告数字都能解释到有效样本与修订顺序**。

仅依赖 Python 3.11 标准库（SQLite + WSGI），无外部服务。

## 能做什么

- **征集**：获准机构按指标 × 预测年份 × 调查轮次提交点值、区间（low/high）、0~1 置信度与理由；
  同目标可多次修订，版本号递增、哈希链防篡改。
- **水位与撤回**：发布申请时冻结水位快照；截止后到达的修订/撤回记为 `late`，
  不覆盖也不抹除；撤回保留"当时参与过共识征集"的事实。
- **幂等与隔离**：同一回执编号重复到达返回首次结果；编号相同而内容不同 → 载荷进隔离区（409），
  人工决定丢弃或受理。
- **规则双审批**：统计人员定义加权均值/（加权）中位数、min_samples、IQR/MAD 异常值规则，
  由不同的审批角色批准；起草人不能自批，发布申请人不能自批。规则版本化，草案也可先回测。
- **匿名化**：机构只能从查询中看到自己的身份与理由，其他贡献者仅显示当次随机匿名码；
  匿名码每次发布重新洗牌，不能跨报告对齐推断。
- **事后闭环**：外部实际值发布后保存共识误差、按机构偏离标记下一轮复核项，
  并可对任意规则版本做历史快照回测（MAE/RMSE/偏差/区间覆盖率）。
- **可恢复**：待批准发布单、到期提醒全部持久化，进程重启后 `/resume` 继续；
  审计日志覆盖全部状态变更。

## 目录

- `src/macro_survey/`
  - `consensus.py`：共识与异常值纯函数（回测复用同一实现）
  - `store.py`：SQLite schema 与事务
  - `service.py`：领域服务（征集/规则/发布/回测/提醒/审计）
  - `api.py`：WSGI HTTP API
  - `app.py`：启动入口
- `docs/architecture.md`：架构与不变量
- `docs/api.md`：HTTP API 参考
- `docs/domain-rules.md`：领域边界
- `tests/`：49 个测试（共识、征集/幂等/隔离、规则/发布/水位/匿名、回测/提醒/重启、HTTP）

## 快速开始

```bash
python -m src.macro_survey.app --db survey.db --port 8080
# 首次引导（仅空库可用），拿到 root token
curl -s -X POST localhost:8080/admin/bootstrap \
  -H 'Content-Type: application/json' -d '{"confirm":true}'
```

典型流转：建机构/用户/指标/轮次 → 统计员设权重、起草规则 → 审批人批准规则 →
机构带 `client_ref` 提交预测 → 发布人申请发布（定格水位）→ 审批人批准 →
实际值发布后记录误差、回测、复核偏离。完整字段见 `docs/api.md`。

```bash
python3 -m unittest discover -s tests -v
```

```bash
python3 -m compileall -q src
```
